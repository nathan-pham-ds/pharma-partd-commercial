A complete, tested Part D pipeline: class share and trend, growth decomposition, geography, specialty mix and k-means prescriber segmentation. CMS was unreachable from this machine, so it was validated on a generated file with the exact CMS schema; one flag switches it to the real data.

Question

Which prescribers should a diabetes brand team call on, and is a class growing because more doctors use it or because the same doctors use more of it?

Data

  • CMS Medicare Part D Prescribers (by Provider and Drug, by Geography and Drug)
  • fetch_cms.py reads the CMS data.json catalogue and picks the newest release per data year
  • Committed outputs come from data/fixture/*_SYNTHETIC.csv (CMS schema, generated values)

Method

  • Drug classes from generic-name stems (-gliflozin, -glutide, -gliptin)
  • DuckDB SQL for share, trend, growth decomposition, geography, specialty
  • k-means on volume, new-class share and growth; segments named from their own profile
  • Suppression rules (<11 claims, blanked beneficiary counts) reproduced and tested
  • Self-contained dashboard; synthetic runs carry a visible banner

Limitations

  • Committed numbers are synthetic: do not quote them as Medicare findings
  • Real Part D is Medicare only (65+ and disabled), not the whole US market
  • CMS suppresses rows under 11 claims, so low-volume prescribers are under-counted
  • Claims are not patients
  • Segmentation uses three features; payer mix and panel size would improve it
